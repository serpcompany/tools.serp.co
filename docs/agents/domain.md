# Domain documentation

This repository uses one shared domain context.

Before naming domain concepts in code, tests, issues, or design work, read the
root `CONTEXT.md` when it exists and use its vocabulary. Read relevant accepted
decisions under `docs/adr/` when that directory exists.

These artifacts are created and expanded lazily when real ambiguity or a durable
trade-off is resolved. Their absence is not a setup error and must not prompt
speculative terminology or empty decision records.

If proposed work conflicts with an accepted ADR, surface the conflict explicitly
instead of silently overriding it.
