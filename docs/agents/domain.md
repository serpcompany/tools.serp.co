# Domain documentation

This repository uses one shared domain context.

Before naming domain concepts in code, tests, issues, or design work, read the
root [domain glossary](../../CONTEXT.md) and use its vocabulary. Read relevant
accepted decisions under `docs/adr/` and follow the
[ADR lifecycle](../adr/README.md).

These artifacts are expanded lazily when real ambiguity or a durable trade-off
is resolved. Do not add speculative terminology or empty decision records.

If proposed work conflicts with an accepted ADR, surface the conflict explicitly
instead of silently overriding it.
